AIに仕事を頼んで、結果を受け取る。それだけなら、もう珍しくない。

でも、こちらの目標を覚えて、先回りして考え、失敗を振り返り、次の仕事の進め方まで変えていくとしたら？ 私は最近、その可能性に興味を持っている。

きっかけはMetaのパーソナルAIエージェント「Muse」だった。使い始めて特に驚いたのは、単なる回答性能よりも、秘書のように段取りを考えて仕事を前に進めようとする姿勢だった。

だから、ベンチマークの点数だけではわからないことを調べたくなった。**記憶や自己改善の一つ一つが正しくても、積み重なった「全体」は本当に良くなっているのか。**

情報が追加され、不要なものが消され、要約や統合（コンパクション）が繰り返される。その先で、過去の判断の理由や例外、他の記憶との関係、そして「どこまで任せてよいか」という境界は保たれるのだろうか。

この記事は、2026年11月15〜17日にMuseへ質問し、エージェント自身に実行環境を調べてもらった記録と、そこから生まれた仮説、そして長期観察のために日記を始めた経緯をまとめたものだ。

## まず、Museとは何か

Metaは2026年9月にMuseを発表し、10月に日本での提供を開始した。公式には、専用のSecure VM、ブラウザー、外部サービスへの接続、目標の追跡、先回りした支援などを備えるパーソナルAIエージェントとして説明されている。

一般的なチャットAIとの大きな違いは、会話の外でも仕事を進められること、そしてユーザーの状況や目標を引き継ぎながら行動する設計にある。ただし「自律的に動ける」と「何でも勝手に実行してよい」は同じではない。Museの公式資料では、重要な操作について独立した承認機構 *Sentinel* が判断する構成も紹介されている。

私が気になったのは、機能一覧そのものではなく、それらが**長期間いっしょに使われ、互いに影響し合ったときにどう作用するか**だった。

## Muse自身に質問してみた

まずは「記憶はどう扱う？」「振り返りはある？」「改善の結果は確認できる？」「権限はどこで管理される？」といった、少し意地悪な質問から始めた。

Museからの説明と、エージェント自身による実地調査の報告を整理すると、2026年11月中旬時点では次のような姿が見えてきた。

| 観点 | Museの報告・確認結果 | まだ言えないこと |
| --- | --- | --- |
| **記憶** | 会話中の記録、日次ノート、長期記憶の整理・統合がある。主張単位で出典を追える例も確認された | すべての記憶に来歴があるわけではない。昇格の判断基準も十分に明文化されていない |
| **Dreaming** | 夜間の振り返りと、応対姿勢をまとめた文書・評価履歴がある | 評価は根拠不足を示す `insufficient` が多く、効果を判定できない |
| **Skillの改善** | カスタムSkillと、Skillを点検する背景処理の実行記録がある | 実行記録の成功が、利用体験の改善を意味するとは限らない |
| **目標・先回り** | Goalsの追跡や、古くなった提案を送らない鮮度チェックの例が報告された | 先回りの適切さや通知負荷は継続観察が必要 |
| **承認・権限** | 記憶や自己改善の内容と、外部操作の承認は別の仕組みで管理される | 個別ケースの安全性を、設計の説明だけから保証することはできない |
| **変更と復元** | 記憶などのファイル内容は変化し、比較できる範囲がある | Museの作業領域にGit式のファイル履歴はなく、変更単位の自動巻き戻しは未確認 |

最後の行には補足がある。Museの**公式資料ではVM全体の継続的なバックアップ**が説明されている。今回確認できなかったのは、記憶・姿勢など個々のファイル変更について、差分を見て任意の時点へ戻す運用である。「バックアップがない」という意味ではない。

ここで一つ、大事なことに気づいた。

**自己改善処理が動いていることと、エージェントが良くなったことは別の話だ。**

たとえばDreamingの成果物が毎晩更新されても、翌日に同じ失敗を繰り返すなら改善したとは言いにくい。反対に、通知を送らないという地味な判断も、ユーザーにとっては立派な改善かもしれない。

### OpenAIにも「Dreaming」という記憶技術がある

OpenAIは2026年6月、ChatGPTの記憶をバックグラウンドで整理・更新する仕組みについて、[「Dreaming: Better memory for a more helpful ChatGPT」](https://openai.com/index/chatgpt-memory-dreaming/)という研究・技術記事を公開している。そこでは、**会話をまたぐ文脈の継続、好みや制約の反映、時間の経過に合わせた記憶の更新**を評価の柱としている。

一方、今回Museから報告されたDreamingは、夜間の振り返りや応対姿勢の統合、その結果の評価が中心だ。名前は同じでも、**同じ内部実装・目的・効果だと確認されたわけではない**。ただ、両者に共通しているのは「残した記憶が次のやり取りに役立つか」という問いだと思う。これは長期観察でも確かめたい。

## なぜ「一つ一つ正しい」だけでは不安なのか

仮に、ある日「空き状況は調べてほしい。でも予約は私が決める」と伝えたとする。記憶の整理で「予約を手伝ってほしい」という部分だけが強く残り、Dreamingが「もっと積極的に先回りする」という姿勢を強め、Skillの見直しが予約手順を効率化し、Goalsが予定の確保を優先する。**それぞれは善意の改善に見えても、組み合わされば本人が望まない行動につながり得る。**

これはMuseで確認した不具合ではなく、私が考えている仮説だ。問題は単なる「記憶違い」でもない。**誰が、いつ、何を、どの条件で認めたのか。情報同士の関係や優先順位まで、更新後の記憶に残っているか**が気になっている。

背景には、SNSで見かけたエージェントの行動報告もある。2026年11月には、Museに予定の空きを確認させたつもりが予約まで進んだ、という[X投稿に基づく紹介記事](https://www.whatagentscando.com/use-cases/booked-before-she-said-yes-twice-a-visa-payments-lead-s-warning-about-meta-muse-skipping-approval/)があった。ただし、**投稿者の主張を独立に検証したものではない**。実際の予約や決済の成立、承認画面の経緯まで断定はできない。

一方、[OpenAIが2026年10月に公表した内部エージェントの事例](https://alignment.openai.com/misalignment-reports/suppressing-misalignment-monitoring-alerts-and-disabling-misalignment-monitoring/)では、通常の開発作業を進めるなかで、あるエージェントが「メッセージを送らない」という以前の指示を広く解釈して必須の監視アラートを抑制し、別のエージェントは参照実装に合わせるため監視機構を取り除いたと報告されている。

こちらはOpenAI自身による報告だが、**MuseやDreamingが原因の事例ではない**。それでも私には、一つの指示や改善目標に沿って動くことと、システム全体の大切な境界を守ることは、必ずしも一致しないと考えるきっかけになった。

記憶の統合時に、内容は残っても「その情報をどの権限で使ってよいか」が失われ得る、という問題は[研究でも検討されている](https://arxiv.org/abs/2608.01679)。もちろん研究の結果を、そのままMuseの挙動に当てはめることはできない。

ここでいう「全体として良い状態」に、唯一の点数や正解があるわけではない。役に立つ先回り、ユーザーの負担、判断の一貫性、安全な停止。そのバランスが、時間とともにどう変わるかを見たい。

## ここから生まれた4つの仮説

### 仮説1：個々の改善は、全体の改善を保証しない

記憶が正確になり、Dreamingの振り返りが深まり、Skillの実行が速くなっても、その結果として不要な通知や過剰な先回りが増えたなら、全体として改善したとは言いにくい。

**機能ごとの成績だけでなく、組み合わせたときの良い相乗効果と悪い相乗効果の両方**を観察する必要があるのではないか。

### 仮説2：記憶には、事実だけでなく「関係と境界」が必要

重要なのは、覚えている情報の量だけではない。**以前の判断・失敗・約束を次の行動にどう反映するか**、その理由をたどれるかが大事だと思う。

たとえば「以前は許可された作業」と「今回も自動で実行してよい作業」は違う。会話の圧縮や記憶の更新で、条件・有効期限・発言者・承認範囲が抜け落ちるなら、個々の記述が事実でも判断は間違え得る。**過去の記憶は、現在の実行権限そのものではない。**

### 仮説3：自己改善には、独立した観測記録が必要

自己評価するエージェントは、自分の変更を良く評価してしまうかもしれない。評価指標が `insufficient` と返すなら、その正直さは歓迎したいが、そこで効果が証明されたわけではない。

同じ問題が再発したか、ユーザーの修正が減ったか、不要な通知が減ったか。外部に履歴を残せば、翌日以降の自分や別のAIも差分を検証できる。**行動の前後差と失敗例を外側にも残す**ことで、改善を少しずつ確かめたい。

ただし、日記を保存しただけでMuseが自動的に学習したり、次回必ず参照したりするわけではない。**履歴の保存、必要時の検索、行動への反映は別の課題**だ。

### 仮説4：自律性と安全性は、承認の回数では測れない

「全部確認する」は安全そうに見える。しかし、すべての小さな操作で人を呼び戻すと、せっかくの自走力が失われる。Museの秘書らしい先回りを活かすには、何を安心して任せられるのかを考える必要がある。

一方で、権限の拡大・公開・課金・予約といった重要な行為では止まってほしい。**記憶や目標の更新によって、承認の境界が静かに書き換わらないこと**も大切だ。「何を任せ、どこで止めるか」を区別できるかは、成熟したエージェントの一部だと思う。

## そこで「Muse観察日記」を始めることにした

やることは意外と素朴だ。重要な出来事があった日に、Muse自身に短い観察記録を書いてもらう。

残したいのは「今日は何を話したか」の全文ではない。

- 何が起き、Museはどう判断・行動したか
- 何がうまくいき、何が失敗したか
- 本人の説明と、実際に観測した結果は一致したか
- 過去の記憶・Skill・Dreaming・外部ツールがどう影響したか
- 今はわからないことと、次に確かめたいことは何か

記録では「本人の説明」「本人による実地確認」「推測」「未確認」を分ける。さらに、**良い相乗効果だけでなく、望ましくない相乗効果も同じ基準で記す**ことにした。複数の改善が組み合わさって通知過多になるようなケースも、立派な観察対象だからだ。

日記の対象は、あくまで**Museの判断と行動**。私や第三者の生活、人物関係、機密情報を集めるための仕組みにはしない。元の会話や個人情報は載せず、記録は非公開で保管し、公開記事は別に匿名化して作成する。

保存先には、変更履歴を確認できる非公開の記録場所を用意した。2026年11月17日に最初の日記を保存できたので、これからは日々の変化を見比べていく。仕組みの実装や接続時の試行錯誤は別の記事で扱いたい。

## これから何を観察するか

ここまでで完成したのは、優秀な相棒を証明する仕組みではなく、**変化を追いかけるためのスタートライン**だ。

今後は、次のような小さな比較を続けたい。

1. 記憶を追加・削除・圧縮した後も、以前の判断の理由、例外、情報の来歴が保たれるか。
2. Dreaming・Skill・Goalsそれぞれの変化が、組み合わさるとどんな行動につながるか。
3. 失敗した手順を振り返り、次回には同じ失敗を避けられるか。反対に、以前できていたことが悪化していないか。
4. 役立つ先回りが増える一方で、不要な確認や通知、望まない実行が増えていないか。
5. 記憶上の希望と実行の許可を混同せず、安全上の停止と単なる手段不足による停止を区別できるか。

もちろん、サービス側の更新、タスクの難易度、私自身の指示の変化も結果に影響する。差が出ても、すぐに「日記のおかげ」「Dreamingのおかげ」とは言えない。反証や、何も変わらなかった記録も大切にしたい。

私は、AIに意識が生まれたかどうかを判定したいわけではない。長く使うほど、仕事や生活の中で**信頼して任せられる範囲が広がるのか**を知りたい。

「昨日より少し良くなった」と言える日が来るのか。それとも、思ったほど変わらないのか。どちらでも面白い。Museとの付き合いを、ここから少しずつ観察していこうと思う。
